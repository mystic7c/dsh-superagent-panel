# 页面说明

面板挂在 DeepSeek Harness Web UI 的左侧栏（入口名「超级智能体」），七个页签对应 Superagent 的完整生命周期：
**消息进来源 → 触发评估 → 接单执行 → 闸门与验收 → 发布**。本页逐个说明每个页签能看到什么、能改什么。

## 概览

值班视图，回答"现在有什么需要我处理"。

- **待办箱**：闸门放行、待验收、干跑待发布、失败、来源异常、引擎异常，按优先级排序，可单条已读。
- **正在执行**：当前在跑的工单与阶段。
- **系统问题**：缺 token、没允许触发人、仓库异常等配置缺口，每条都带一个直达设置页的按钮。
- **过去 24 小时**：到达 → 过滤 → 接单 → 执行的漏斗，**运行质量**（成功率、平均耗时、自动修复次数、Top 失败原因）、
  策略规则命中与拦截统计、**系统脉搏**（引擎/执行器/轮询状态）。
- 首次使用时顶部显示四步配置清单（保存 Octo token → 添加监听群 → 绑定仓库 → 打开引擎）。

**归属**：概览只做只读汇总与入口。暂停/未启用的状态由顶部状态条和执行页的自动化条负责，概览不再重复一条暂停横幅；
配置项（包括「还有 N 项待配置」）在这里只保留一份清单，点进去改都在设置页。

## 来源

Octo 消息从进来到变成工单的过程。

- **原始信号台账在最前**（这是本页唯一的主体）：每条消息的判定（接单 / 忽略 / 跳过 / 失败）与原因，可重放、可人工标注
  正确/误报/漏报，支持文本、状态、仓库、原因、时间范围筛选与分页。台账为空时不摆一排筛选控件。
- 台账是消息的**唯一**去处：不再单独列一份「被过滤消息」（那是台账里状态=被过滤的子集，同一批消息列两遍）。
  Octo 卡片的「查看被过滤」只是把台账筛到「被过滤」并滚过去。
- 监听群与代码仓库各一张运营卡片：状态、24 小时到达/过滤/接单、执行工单/待合并 MR/UAT，以及「打开项目」「管理仓库」。
  仓库的远程地址、目标分支、令牌、本地路径、验证与验收方式**只在设置 → 仓库里编辑**，这里不再复述。
- 页头一行健康摘要（已启用 N/M、上次同步）；「检查新消息」（只读试运行，不写入状态、不建工单）在本页和顶部状态条各有一个入口，
  不再在其他页面重复。

## 触发

评估视图：一条消息为什么被接单或被忽略。

- 线程列表与线程详情：线程信息（来源、创建、最近活动、消息数、工单数）、产生的工单、消息时间线
  （每条消息去了哪、为什么）。
- 判定台账**不在这里复述**：详情里的「查看评估记录（n）」跳到评估页，并且只显示这个线程的判定。
- 支持按文本、仓库、原因、时间范围筛选与分页。

## 评估

决策台账（只读）。

- 接单 / 忽略两类决定的列表、命中规则与置信度。**判定只在这里列一次**，其他页签引用而不重画。
- 支持 `threadKey` 过滤：从触发页跳进来是「这个线程的判定」，页内可一键显示全部线程。
- 不展示原始判定 JSON：界面上出现的是结论、原因、强度与规则结果，原始数据留在 state 里，需要时走日志或 API。
- 按文本、仓库、原因、时间范围筛选与分页，**筛选状态写入 URL**，可直接分享当前视图。
- 模型改判与人工改判的**分歧视图**；shadow 模式下同时显示模型意见但不参与执行。

## Bot

Bot 是「一类活由谁来做」的定义。这里管全部 Bot，设置页只管工作流本身。页签在「评估」和「执行」之间——先定谁来做，再看队列。

- **列表 / 详情**：左边是 Bot 列表（内置 `generalist` / `reviewer` 置顶，不可改不可删），点一行右边换成这个 Bot 的信息；
  「新建 Bot」在列表下方。列表只写「名称 + 标识」。待沉淀的 `adhoc:<hash>`（至少跑过 3 次、还没存成 Bot）列在列表末尾，
  点一下把名字、说明、什么时候派给它与后端预填进编辑器，确认后手动保存——不自动写入。
- **新建只问三件事**：名称、一句话说明、后端。标识由名称派生（小写短横线，重名自动加后缀），不让人填；名称为空时
  「创建」是禁用的。
- **编辑器只有五项**：名称 / 后端 / 一句话说明（≤120 字）/ 什么时候派给它（`whenToUse`，≤300 字）/ 角色提示词。
  「什么时候派给它」与「一句话说明」不是重复：前者是决策模型判断归属时读的，后者是给人扫列表的。没有能力勾选、没有工具
  边界、没有预算输入框——Bot 不声明能力、也不申请权限。预设 / 模型 / 思考深度 / Skill 偏好放在「高级设置」里，可留空。
  **高级设置按后端给控件**：`GET engine/bots/catalog` 读宿主的预设、provider → 模型清单与已发现的 Skill；DSH 用下拉
  选预设与 provider/model、Skill 用多选（没列出来的可手填）；Claude / Codex 的预设置灰（它们只有自己的默认配置），
  模型退化成手填 id。
  提示语说明留空时到底继承什么，不再指向并不存在的「设置 → 运行」。
- **详情栏**：身份五项、只读预算（继承自「设置 → 运行」的数值）、「谁会把活派给它」（默认 Bot / 哪些仓库指定了它 /
  工单上可手动指定）、最近表现（最近 20 单的通过率、平均返工、闸门通过率、中位耗时、最近一次）——统计按 `run.botId`
  与运行时留下的 `run.bot` 快照聚合，改 Bot 不会改写历史。
- **保存期校验**：错误码与说明就地显示（标识非法、说明或 whenToUse 超长、后端未启用、预设未知等）。
- **后端与派单**：三个后端各自的状态（派单可用 / 没有冒烟证据 / 版本变了复核中 / CLI 不在）+ 一句原因 + CLI 路径 +
  核验时间，以及重新核验按钮。版本变了的后端在复核期间不参与派单；保存后端配置后会自动核验一次。
- Bot 文件只从状态目录读取，仓库里的同名文件会被忽略（详情页会提示这一点）。首次读到 v2 文件会备份为 `.bak` 并写回 v3。

## 执行

执行器与工单队列。

- 执行器负载、暂停/恢复、手工建单、工单队列台账（等人处理的排在最前）。
- 视图选项：按阶段或按仓库分组、多种排序、显示已结束；**「已忽略」切片**显示失败后被人放弃的工单。
- 「显示已结束」这一个开关是「要不要看已结束」的唯一入口（计数在阶段 chip 上）；开关打开后，已结束组默认只列最近 10 张，
  底部的「显示其余 N 张」把它展开。以前这里有三处重复的展开入口，现在只剩开关 + 封顶展开两级。
- 手工建单：本地填标题与正文，直接进入执行队列；正文或追加要求里写 `tkt_…` 即引用既有工单，执行时把那张工单的报告（无报告则正文）作为背景上下文交给 worker。
- **工单详情**是面板最重的一页：
  - 改动内容（仓库、分支、验证方式、执行总结、改动文件与逐文件 diff）、需求正文；
  - 验收（轮次、逐项检查、人工 accept/reject，失败项带修复提示）；
  - 自动化（固定间隔 / 每天 HH:mm / 次数上限，显示下次运行与跳过原因）；
  - 各闸门结果、运行记录（trigger、停止原因、handoff、执行轨迹、报告、活动流；DSH worker 的行内 run ID 可直接打开执行器 Session（会话已归档时先取消归档；客户端会话列表还没投影出这个会话也照样交给宿主去开），CLI worker 没有可打开的会话，那里保留复制）；
  - **追加要求**：输入后自动干跑重跑，保留当前工作树改动；
  - 干跑完成后主行动变为「发布 MR」；MR 卡显示草稿与过期 CI 提示；
  - 运行中可请求停止（真正取消 worker 与子进程后确认），中断的运行可继续，worker 提问可回答；
  - 每一轮记录这段运行用的**Bot**：三层逐条命中理由（1 显式·仓库指定 / 1 显式·工单手动指定 / 2 挑选·决策模型 /
    3 默认·`executor.bot`）、模型给出的 `because`、当时的候选集合、「没进候选」的后端与原因；`cacheHit` 与降级
    （模型不可用 / 失败 / 选了候选之外 / 认为都不合适 / 没有可用 Bot）用标签标出，失败/被拒/超时的执行轨迹直接展开；
    可「换 Bot 重跑」（只影响新一轮，不改工单）。

## 设置

除评估与提示词（只读参考）外均可写，保存前展示字段级差异，每次保存自动生成可回滚快照。

- 页头右上有整套设置唯一的「重新加载配置」、变更历史与复制配置路径。
- **来源**：Octo token、启用引擎、允许任意人类/发送者名单、轮询间隔、监听群与仓库绑定（绑定的改动进入草稿，
  保存时按高风险变更确认后写回）。
- **运行**：执行器开关、自动执行、接单/派发暂停、MR 方式、执行超时、返工预算。
- **Worker**：多后端启用（DSH / Codex / Claude，各带模型与 CLI 路径）与预览/兜底用的默认后端。没有路由模式、任务类型偏好表、
  能力矩阵，也没有降级后端：实际执行的后端由派单选中的 Bot 自己决定，执行中不换后端、不重试。
- **派单**（只读）：候选怎么来（后端此刻可用）、怎么选（读每个 Bot 的 whenToUse 的一次模型调用）、什么时候不调模型
  （显式指定 / 只有一个候选 / 缓存命中）、失败怎么办（回退默认 Bot 并记降级原因）、危险行为在哪拦（闸门 / 沙箱 / 拒绝规则），
  以及两种显式指定（仓库指定、工单手动指定）。
- **写权限**：推分支、回群消息、合并 MR。
- **仓库**：GitLab token、新增/编辑/停用仓库（名称、本地路径、远程地址、GitLab 项目、基分支/目标分支、验证方式、
  验收方式、UAT/健康检查地址、闸门），以及配置文件与路径这类全局事实。
- **变更历史**：查看与恢复 `live.json` 的历史快照。

手工建单只在执行页（设置页不再有第二份表单）；检查 UAT 只在来源页的仓库卡片上。没有删除仓库的操作：停用后再编辑即可，
worktree 与 `repairHint` 这类更细的字段仍在 `live.json` 中配置，格式见设置页的「复制路径」与示例配置。
